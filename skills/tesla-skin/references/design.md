# 固定白版合成与检查

## 默认流程

简短描述 → 锁定明确约束并补齐设计 brief → 整体构图与配色 → 内置生图生成连贯背景及透明主体 → 设计 JSON → 固定白版合成 → 整体视觉复核 → 必要时压缩 → 校验最终 PNG。

将需要创造的图案交给 AI；像素尺寸、岛块位置、旋转和透明轮廓由程序处理。不再要求模型重画整张白版。无需用户额外提供风格参考图。修改已有作品时，优先使用已保存图案素材和设计 JSON，避免无关部位随机变化。

主体素材强调正立、完整、真实透明背景、无杂点和标签；连贯背景则允许满版不透明印花，不需要把每朵花、每根丝带拆成孤立图标。两类都不画车型光照和导向边框，不让模型重画整张 UV。配色服务主题，不机械限制为极少颜色；导出后按实际体积决定是否压缩。

## 从一句话补齐设计

用户说“做一款 Hello Kitty”“海洋主题”或“酷一点”即可开始。先提取明确约束，再由助手做缺省设计决策。缺少配色、纹样、位置或细节不是暂停制作的理由；不需要用户先提供完整设计 brief，也不要求参考图片。

补充以下内容，但不要机械地把每项变成一块独立贴纸：

- **主题与气质**：用具体视觉语言表达主题，确定可爱、清爽、运动、复古等整体气质；只给气质时可以采用原创抽象构图，不强行添加角色。
- **配色关系**：明确底色、主要图案色和少量强调色，以及深浅/明暗关系，保持全车一致。用户已指定的颜色不能擅自改掉。
- **主图与关联细节**：选择主视觉、适合它的姿态/装饰/纹样，说明哪些大、哪些小、哪些聚集、哪些留白；关联元素需要服务主题，不是随意凑满。
- **贯穿构图**：决定丝带、海浪、线条、色块或其他连接方式如何从车头/前门延续到后门与后侧围，哪些前景与背景叠压，避免每块部件重新起一个孤立画面。
- **分区分工**：引擎盖形成清晰焦点，侧面使用连续画稿和主次变化，尾部用呼应的元素收尾，镜盖/细条采用缩减细节或安静底色。无需强行让每个部件都有角色或大图。
- **密度与边界**：按主题分配繁简、对比和留白；保护脸部/文字和明确禁用项。丰富度来自构图、比例和层次，不只是元素数量。

brief 用简短自然语言保存为同名 `.brief.md`，包含“用户明确要求”和“本次补充设计”。把补充设计编入真实背景/主体生图提示词，并落实为配色、共享背景分组及图层排布；不能描述了贯穿丝带却最终只放几个独立图标。生成前用一至三句话说明方向后直接制作，不增加默认确认步骤。

### 补全示例（方向示例，不是固定配方）

| 简短要求 | 可直接采用的完整方向 |
| --- | --- |
| Hello Kitty | 草莓粉与奶油白，莓红强调；Kitty 融入缎带花环主视觉，丝带串起前后门，花朵/爱心沿路径形成疏密变化，局部格纹与尾部蝴蝶结呼应，无额外标语。 |
| 海洋主题，清爽一点 | 浅海蓝与珍珠白，少量珊瑚色；柔和海浪贯穿侧面，以流动曲线、大小不同的气泡和稀疏水纹丰富细节，引擎盖留出清晰焦点，顶部和细条保留较大留白。 |
| 极简黑金 | 石墨黑占主导，暖金细线沿车身延伸，通过转折、粗细和局部断续产生节奏，尾部用小范围金色呼应，不自动加入角色、花朵或满版纹样。 |
| 纯黑底，只要一条红线 | 保留纯黑与单一红线，只细化线条走向、比例和跨部件衔接，不补充其他图案、文字或额外颜色。 |

这些例子帮助理解怎样补全，不要求复刻。不要把某次用户的“装饰多一点”当成所有未来皮肤必须花哨的规则。详细要求只补未指定部分；局部修改只补充对应部位并保留其他设计。

## 整体设计优先

先确定一个主要视觉、连接部件的色块/线条及有疏密变化的纹样。通过同一装饰系统的大小、重叠和留白形成统一关系；避免所有部件都以相同大小、相同位置摆同一图标。用户要求丰富时，可用连贯印花、丝带、花纹和局部留白；用户要求极简时减少元素，但仍保留整体关系。不能用“加更多随机小图标”代替构图。

脸部和文字不能意外跨缝或被裁掉；装饰背景、色带、重复纹样可以延伸到部件边缘并有意裁切。安全边距只保护需要完整阅读的主体，不应导致全车背景空白。主图可以与背景形成适度叠压，而不是每个主体外围都留一圈机械空白。

## 车型选择

设计 JSON 用 `"model": "model-y"` 或 `"model": "model-3"` 选择各自模板。缺省字段用于兼容旧版 Model Y 设计，未指定车型的用户请求仍须分别制作两个车型。Model 3 校验时使用 `--template "<skill-dir>/assets/model3-template.png"`；Model 3 分区及方向是基于白版的推定，App 和实车效果待确认。

## 设计 JSON

图片路径相对于 JSON 所在目录。每个部件可以有多个图案层，列表顺序即叠放顺序。示例中的主题只是语法示例，不是所有新设计的默认风格：

```json
{
  "base_color": "#fff2df",
  "backgrounds": [
    {
      "image": "side-print.png",
      "parts": ["left_front_fender", "left_front_door", "left_rear_door", "left_rear_quarter"],
      "rotation_cw": 90
    },
    {
      "image": "side-print.png",
      "parts": ["right_front_fender", "right_front_door", "right_rear_door", "right_rear_quarter"],
      "rotation_cw": 270,
      "mirror": true
    }
  ],
  "parts": {
    "hood": [{"image": "motif.png", "scale": 0.85}],
    "left_front_door": [{"image": "motif.png", "scale": 0.75}],
    "right_front_door": [{"image": "motif.png", "scale": 0.75}],
    "left_rear_door": [{"image": "paw.png", "scale": 0.35}],
    "right_rear_door": [{"image": "paw.png", "scale": 0.35}],
    "rear_center": [{"image": "paw.png", "scale": 0.35}]
  }
}
```

- `base_color`：不透明底色。车身材质和明暗交给车型渲染，不在贴图底色中烘焙假阴影。
- `backgrounds`：可选背景列表，先于主体绘制。每项用 `image` 指定单帧 PNG（允许不透明），`parts` 指定一个或多个不重复的部件，`rotation_cw` 及 `mirror` 控制画稿方向。同组部件使用**同一次缩放和定位**，不会在每个岛块重新起图。图像按 cover 适配整组包围框，因此应按分组的长宽比生成画稿。
- 背景可选 `source_box: [left,top,right,bottom]`（0–1，默认整图），可将同一画稿的纹样带用于保险杠等部位。装饰背景可以镜像；含文字、角色或非对称标志时应另画另一侧或单独安排主图，避免机械镜像。
- `parts`：部件 ID 见 [../assets/parts.json](../assets/parts.json)。未指定部件保留统一底色。
- `image`：单帧透明 PNG，先清除 alpha ≤12 的弱透明杂点和少于 64 像素的独立噪点，再按实际 alpha 边界取图案。
- `scale`：在可用部件区域内等比适配后的比例，0.05–1，默认 0.75；不表示拉伸至整个岛块。
- `center`：可选 `[u,v]`，范围 0–1，默认 `[0.5,0.5]`，相对于部件安全放置框。无法完整放入安全区时会逐步缩小；仍放不下则报错，不能静默裁掉主体。
- `rotation_cw`：可选 0/90/180/270，**仅旋转图案层**。默认从部件配置读取；非方向性纹样可显式选择 0。不要因展开图看起来“倒了”而撤销正确 UV 旋转。
- `mirror`：可选布尔值，先镜像再旋转。含文字或非对称标志时不能机械镜像。

默认按车外看车头/车侧时正立处理：引擎盖 180°，展开图左侧门板/侧围 90°，右侧 270°。引擎盖因此在俯视控制界面中可能倒置，这是选定观看优先级的结果。用户明确要求俯视正立时才覆盖引擎盖为 0°，并说明视角取舍。

## 命令

```text
python "<skill-dir>/scripts/compose_skin.py" "<design.json>" "<skin.png>" --report "<skin>.composition.json" --review "<skin>-review.png"
python "<skill-dir>/scripts/validate_skin.py" "<skin.png>" --report "<skin>.validation.json"
```

`--review` 输出部件恢复到观看方向的平面检查图；同侧分区保持共同 UV 尺度和位置，不逐块拉成一样大，以便观察连续背景。它不是 3D、App 或车机效果图；实际 App 车前、车侧、车后仍需分别确认，不能从合成报告自动标记通过。

## 几何、边缘和安全区

- 从原始模板提取 16 个白色连通区域，以原模板 alpha 作为最终透明轮廓。模板 RGB 中的黑色分区描边是定位辅助，**不能画进成品**。
- 部件固定不动。透明主体完整放入内缩区域：引擎盖 10 像素，主要侧围/门板 8 像素；装饰背景则满版映射到整组部件，外扩 2 像素 RGB 覆盖导向线边缘，同时保护未选部件的白色区域。最终仍用原 alpha 裁切。
- 门板靠车窗的边缘额外预留 20% 放置宽度，降低脸部/文字与门把手冲突。该区域是保守设计安全区，不是已校准的精确门把手 UV 坐标。
- 底色覆盖整个实际模板 alpha 轮廓，消除 AI 输出的轮廓漂移、额外彩边和导向黑边。图案中的弱透明噪点在放置前清理；不能用颜色量化“碰巧抹掉紫色”代替清理。
- 不凭颜色一律删除紫色/黑色，避免破坏用户原本要求的主题；先用透明关系、连通区域和模板范围判断噪点。保留透明边缘底下的车漆 RGB，压缩也不主动填黑。
- 清理和放置可能移除细小装饰或缩小主体，必须查看最终图。若误删了用户需要的细节，应修改/重新生成素材，不能直接忽略差异。

## 分阶段验收

1. 文件：尺寸、PNG、文件名、体积。
2. 结构：完整模板轮廓、留空、分区覆盖、连细弱 alpha 在内的越界杂点。
3. 图案：人工检查方向、清晰度、主体完整、安全区、配色与跨部件连续性。
4. App 展示：车前、车侧、车后分别检查。用户截图只能确认截图中可见的部位；截图所属成品版本不明确时不能套用到新版本。
5. 实车：单独记录导入车型、软件版本和效果；没有证据时保持待确认。

“脚本通过”“App 已显示”“实车确认”是不同结论。尺寸错误时仍输出按尺寸缩放模板的诊断指标，但总体保持不合格，不把诊断缩放当成实际修复。
