# Model Y 白版与方向依据

## 权威顺序

用户确认的车型和观看约定确定目标；对应白版确定几何；用户提供的实际 App 展示证据优先于 Sample 的方向惯例。样例不是几何标准，也不是新主题的风格参考。部分样例在中心留空处画了车顶或铺了白色背景，这些内容不能进入本白版的透明洞。

内置模板与用户提供的原图逐字节相同，SHA-256：
`145e56ff1d9d3d5d3c3bac4ce1b331387858cb3ee7f17dce7d1de2100bf42a4b`。

模板为 RGBA；大量留空是 `(0,0,0,0)`，外围也有 `(255,255,255,0)`。不能仅按 RGB 白色提取分区，更不能把图像查看器显示的黑底视为车漆。以 alpha 和亮度共同识别白色岛。最终只继承模板的 alpha 轮廓与抗锯齿；RGB 中的细黑分区描边用于定位，不应绘入车漆。

## 样例证据与限制

- `Model_Y_Pre-20_103310.png` 的侧门文字、山形条带，以及 `Model_Y_Pre-20_104526.png` 的人物，支持左侧图案顶端朝 +x、右侧朝 -x 的惯例；上下门板沿同一方向排列。
- `Model_Y_Pre-20_103328.png`、`Model_Y_Pre-20_130513.png` 的中央上方主体为倒向；`Model_Y_Pre-20_104526.png` 的主体为正向。不能把任一作者的引擎盖方向当作实车事实。
- `Model_Y_Pre-20_104434.png`、`Model_Y_Pre-20_130552.png` 等在中心洞中绘有图案；本技能不得照搬这个差异。
- 源 Sample 分辨率有 629、740、1024、1088，不应据此调整白版尺寸。参考关系已记录在本文，安装包无需依赖源 Sample。
- 部分方向已有用户提供的 App 展示证据，见下一节；横幅文字、右侧完整展示、后视角及跨缝连续性仍需逐项确认。App 截图不是所有车型/软件版本的通用校准，也不等于实车验证。

## 2026-11-03 用户提供的 App 展示反馈

两张截图分别为俯视控制页和车前侧主视角。图案主题与当前橘猫候选一致，但最终导入文件及预处理步骤未确认，不能根据截图认定 1254×1254 原图直接通过了导入。

- 引擎盖旧默认（素材头朝画布上方）在车前侧看是倒置，俯视控制页则正立。新默认选择车外观看优先，因此程序对正立素材执行 180° 旋转；这是明确的展示约定，而不是宣称所有视角都能同时正立。
- 车门旧主体在车前侧截图中横躺。旧提示词要求了 ±90°，但 AI 未执行。新合成器直接应用部件旋转，平面方向检查图供人工复核；实际 App 新版本仍需确认。
- 门缝和后视镜边缘可见紫色细线。旧未压缩候选含低透明度洋红像素，可能与边缘杂色有关，但截图不足以确认具体成因。新流程不依赖压缩恰好去掉杂色，而是清理素材弱透明噪点、固定模板 alpha、不画模板黑边并检查所有非零越界 alpha。
- 截图只证明当时设计能在 App 模型中显示，不能自动更新新版本的 App 或实车状态。只保留这些非个人化观察，不把包含用户通知、位置等信息的原始截图发布到仓库或技能包。

## 提示词要点

AI 只生成正立、完整、透明背景的独立图案，强调不要输出 UV 图、车模、场景、导向描边、杂点或水印；几何和旋转由合成器完成。不同部位复用同一主题素材，保持配色一致。底色平涂，主体远离接缝和门把手安全区。具体设计 JSON 与命令见 [design.md](design.md)。

## 已观察到的生图限制

2026-11-03 的橘猫主题实际测试中，首图和一次定向修正都返回 1254×1254，而不是要求的 1024×1024；两张分别为 1,607,264 和 1,449,204 字节。门板主体仍正立于画布，未执行要求的侧向旋转；透明区可见杂点和轮廓偏差。两张均为未通过检查的候选图。

这不是所有后续生成都会失败的结论，但证明了“提示词中指定”不等于“实际满足”。尺寸、透明范围、体积必须读取文件检查，侧向排布必须查看图片；不要宣称纯生图已经稳定产出可用车机贴图。按技能的一次修正上限处理，不能无限重试，也不能在报告中隐去失败。
