# 固定白版合成与检查

## 默认流程

文字主题 → 内置生图生成正立透明图案素材 → 编写分区设计 JSON → `compose_skin.py` 固定白版合成 → 视觉检查 → 必要时压缩 → 校验最终 PNG。

将需要创造的图案交给 AI；像素尺寸、岛块位置、旋转和透明轮廓由程序处理。不再要求模型重画整张白版。无需用户额外提供风格参考图。修改已有作品时，优先使用已保存图案素材和设计 JSON，避免无关部位随机变化。

生成素材时强调：正立、主体完整、真实透明背景、留白充足、无阴影和光照、少量稳定色彩、无杂点、无文字标签。不把整张 UV 图当素材传给合成器；一张素材应是一个可独立摆放的主体或小纹样。若素材为花纹/带透明边缘的纹样，也遵循同一规则。

## 设计 JSON

图片路径相对于 JSON 所在目录。每个部件可以有多个图案层，列表顺序即叠放顺序。示例中的主题只是语法示例，不是所有新设计的默认风格：

```json
{
  "base_color": "#fff2df",
  "parts": {
    "hood": [{"image": "motif.png", "scale": 0.85}],
    "left_front_door": [{"image": "motif.png", "scale": 0.75}],
    "right_front_door": [{"image": "motif.png", "scale": 0.75}],
    "left_rear_door": [{"image": "paw.png", "scale": 0.35}],
    "right_rear_door": [{"image": "paw.png", "scale": 0.35}],
    "rear_center": [{"image": "paw.png", "scale": 0.35}]
  }
}
```

- `base_color`：不透明底色。车身材质和明暗交给车型渲染，不在贴图底色中烘焙假阴影。
- `parts`：部件 ID 见 [../assets/parts.json](../assets/parts.json)。未指定部件保留统一底色。
- `image`：单帧透明 PNG，先清除 alpha ≤12 的弱透明杂点和少于 64 像素的独立噪点，再按实际 alpha 边界取图案。
- `scale`：在可用部件区域内等比适配后的比例，0.05–1，默认 0.75；不表示拉伸至整个岛块。
- `center`：可选 `[u,v]`，范围 0–1，默认 `[0.5,0.5]`，相对于部件安全放置框。无法完整放入安全区时会逐步缩小；仍放不下则报错，不能静默裁掉主体。
- `rotation_cw`：可选 0/90/180/270，**仅旋转图案层**。默认从部件配置读取；非方向性纹样可显式选择 0。不要因展开图看起来“倒了”而撤销正确 UV 旋转。
- `mirror`：可选布尔值，先镜像再旋转。含文字或非对称标志时不能机械镜像。

默认按车外看车头/车侧时正立处理：引擎盖 180°，展开图左侧门板/侧围 90°，右侧 270°。引擎盖因此在俯视控制界面中可能倒置，这是选定观看优先级的结果。用户明确要求俯视正立时才覆盖引擎盖为 0°，并说明视角取舍。

## 命令

```text
python "<skill-dir>/scripts/compose_skin.py" "<design.json>" "<skin.png>" --report "<skin>.composition.json" --review "<skin>-review.png"
python "<skill-dir>/scripts/validate_skin.py" "<skin.png>" --report "<skin>.validation.json"
```

`--review` 输出部件恢复到观看方向的平面检查图，供检查脸部和文字方向；这不是 3D、App 或车机效果图。实际 App 展示的车前、车侧、车后仍需分别确认，不能从合成报告自动标记通过。

## 几何、边缘和安全区

- 从原始模板提取 16 个白色连通区域，以原模板 alpha 作为最终透明轮廓。模板 RGB 中的黑色分区描边是定位辅助，**不能画进成品**。
- 部件固定不动，图案等比缩放并完整放进内缩区域；引擎盖内缩 10 像素，主要侧围/门板 8 像素，小部件按配置缩减。
- 门板靠车窗的边缘额外预留 20% 放置宽度，降低脸部/文字与门把手冲突。该区域是保守设计安全区，不是已校准的精确门把手 UV 坐标。
- 底色覆盖整个实际模板 alpha 轮廓，消除 AI 输出的轮廓漂移、额外彩边和导向黑边。图案中的弱透明噪点在放置前清理；不能用颜色量化“碰巧抹掉紫色”代替清理。
- 不凭颜色一律删除紫色/黑色，避免破坏用户原本要求的主题；先用透明关系、连通区域和模板范围判断噪点。保留透明边缘底下的车漆 RGB，压缩也不主动填黑。
- 清理和放置可能移除细小装饰或缩小主体，必须查看最终图。若误删了用户需要的细节，应修改/重新生成素材，不能直接忽略差异。

## 分阶段验收

1. 文件：尺寸、PNG、文件名、体积。
2. 结构：完整模板轮廓、留空、分区覆盖、连细弱 alpha 在内的越界杂点。
3. 图案：人工检查方向、清晰度、主体完整、安全区、配色与跨部件连续性。
4. App 展示：车前、车侧、车后分别检查。用户截图只能确认截图中可见的部位；截图所属成品版本不明确时不能套用到新版本。
5. 实车：单独记录导入车型、软件版本和效果；没有证据时保持待确认。

“脚本通过”“App 已显示”“实车确认”是不同结论。尺寸错误时仍输出按尺寸缩放模板的诊断指标，但总体保持不合格，不把诊断缩放当成实际修复。
